01 / JAVASCRIPT

Make the source less readable.

Transform built JavaScript with obfuscation and an AES-GCM constant pool. Standalone mode unlocks synchronously before your code runs.

ai-shield protect ./dist --ext js --standalone
Built JS → protected JS in the same directory

Standalone includes its decryption key. Keep server secrets on the server.

02 / APPLICATIONS

Put a native loader around it.

Bundle a Node.js or Python folder with its entrypoint and assets, or wrap a native binary for the matching operating system.

ai-shield pack ./application --entry main.js
--out ./protected-application
Application + assets → a packaged executable

Node.js and Python runtimes remain prerequisites on the target machine.

Before you ship
A few things
to know.
Pick the right mode and use stable data paths. The details make the difference in deployment.


What does standalone protection provide?
Obfuscation and encrypted constant pools with synchronous unlocking. The key is included in standalone output, so this mode does not provide access control. Enterprise mode uses an Ed25519 license gate. See the mode and deployment guidance.


Do packaged Node.js and Python apps need a runtime?
Yes. Packaging includes your files and the native loader, while Node.js or Python must be available on the destination machine. Use a matching OS and architecture. macOS binaries are not notarized.


Where should an application save its data?
Use the inherited working directory or an explicit persistent directory. Use __dirname / __file__ to read bundled assets. Modified extraction directories are retained and reported, but are not reused at the next launch. Python caches can trigger that notice.


What is included in the public repository?
The website, documentation and binary releases. The core implementation is maintained privately. Each release archive includes the CLI, loader, README, license, third-party notices and build revision.
