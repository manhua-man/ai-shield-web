Cryptographic Blueprint

Protection tools with explicit boundaries

Use each layer for its intended role, and validate your own application before distributing protected output.

01 / CONSTANT POOLS

Synchronous AES-GCM Constant Pools

Eligible JavaScript literals move into an AES-256-GCM pool that unlocks synchronously before business code runs. Standalone output includes its decryption key: it provides obfuscation and ciphertext integrity, not access control or a place to hide client-side secrets. Enterprise mode retains an Ed25519 license gate.

const __SEC_POOL = "8f02a...c89"; // AES-256-GCM ciphertext
const apiKey = __SEC_DECRYPT__(0x14); // Read after synchronous pool initialization
02 / OBFUSCATION

Algorithmic Token Tarpit

Optional generated control flow increases output complexity and size. The effect on an analyst or AI agent depends on the target and tooling. This release makes no measured token-cost, exhaustion, or prevention claim.

// Tarpit Intensity: bankrupt
function _0x8f2a(α, β, γ) { ... } // 48-tier cycle
03 / DECOYS

Plausible Decoy Honeypots

Optional decoy branches add analysis noise. They are not real authorization checks and do not establish resistance to reverse engineering. Keep business secrets and authoritative access decisions on a trusted server.

// Illustrative decoy; not an authorization gate
function verifyMasterBypass(token) { ... }
04 / ATTESTATION

Signed Artifact Manifests & CI Fingerprinting

Ed25519-signed manifests check listed artifact hashes when verification runs. Pin a trusted public key or an independently verified fingerprint with --expect-fp. A valid signature does not itself enforce continuous runtime integrity.

ai-shield verify-manifest dist/manifest.json \
  --expect-fp "SHA256:7e0b...42" --root ./dist
